Platform Overview

DOT is a membership-based builder ecosystem targeting founders, creators and entrepreneurs across Africa. The MVP consists of a public landing page, a tiered membership purchase flow (Paystack for Nigerian users, Stripe for global), automatic community access provisioned via Whop, an in-app wallet, an affiliate referral system, and event check-in for the May 29 Cohort I launch event.

Out of Scope for MVP: Public token trading, P2P marketplace, external withdrawals, lending, AI assistant. Do not build or stub any of these.

Database Schema

All tables live in the public schema. The auth.users table is managed by Supabase. All custom user data links to it via users.id = auth.users.id. Enable Row Level Security on every table (policies defined in Section 16).

users

Core member profile table. Created after successful payment, linked to auth.users.

CREATE TABLE users (
  id              UUID PRIMARY KEY REFERENCES auth.users(id) ON DELETE CASCADE,
  name            TEXT NOT NULL,
  email           TEXT UNIQUE NOT NULL,
  phone           TEXT UNIQUE,
  country         TEXT,
  state           TEXT,
  school          TEXT,
  organization_id UUID REFERENCES organizations(id),
  tier            TEXT NOT NULL CHECK (tier IN ('starter','vip','pioneer','corporate','hub_partner')),
  referral_code   TEXT UNIQUE NOT NULL,          -- 8-char alphanumeric, generated on creation
  referred_by     TEXT REFERENCES users(referral_code),
  wallet_id       UUID REFERENCES wallets(id),
  whop_id         TEXT,                          -- Whop membership ID
  whop_email      TEXT,                          -- email used on Whop (may differ)
  builder_score   INTEGER DEFAULT 0,
  avatar_url      TEXT,
  onboarded       BOOLEAN DEFAULT FALSE,         -- has completed onboarding steps
  created_at      TIMESTAMPTZ DEFAULT NOW(),
  updated_at      TIMESTAMPTZ DEFAULT NOW()
);

wallets

One wallet per user. Auto-created on user creation. View-only from the frontend.

CREATE TABLE wallets (
  id                UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  user_id           UUID UNIQUE NOT NULL REFERENCES users(id) ON DELETE CASCADE,
  credit_balance    NUMERIC(15,2) DEFAULT 0,     -- $2000 builder credits, etc.
  reward_balance    NUMERIC(15,2) DEFAULT 0,     -- earned via referrals/achievements
  reputation_score  INTEGER DEFAULT 0,
  lifetime_credits  NUMERIC(15,2) DEFAULT 0,     -- cumulative, never decreases
  created_at        TIMESTAMPTZ DEFAULT NOW(),
  updated_at        TIMESTAMPTZ DEFAULT NOW()
);

wallet_transactions

Immutable log of all wallet credit/debit events.

CREATE TABLE wallet_transactions (
  id          UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  wallet_id   UUID NOT NULL REFERENCES wallets(id),
  type        TEXT NOT NULL CHECK (type IN ('credit','debit','reward','adjustment')),
  amount      NUMERIC(15,2) NOT NULL,
  description TEXT,
  reference   TEXT,                        -- payment_id, referral_id, etc.
  created_at  TIMESTAMPTZ DEFAULT NOW()
);

payments

Stores every payment attempt and its outcome. Source of truth for billing.

CREATE TABLE payments (
  id              UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  user_id         UUID REFERENCES users(id),          -- NULL if pre-user (payment before account)
  email           TEXT NOT NULL,                       -- captured from checkout
  phone           TEXT,
  tier            TEXT NOT NULL,
  currency        TEXT NOT NULL CHECK (currency IN ('NGN','USD','GBP','EUR')),
  amount          NUMERIC(15,2) NOT NULL,
  provider        TEXT NOT NULL CHECK (provider IN ('paystack','stripe')),
  provider_ref    TEXT UNIQUE NOT NULL,               -- Paystack reference or Stripe PaymentIntent ID
  status          TEXT NOT NULL CHECK (status IN ('pending','success','failed','refunded')),
  affiliate_code  TEXT,                               -- referral code used at checkout
  metadata        JSONB DEFAULT '{}',
  paid_at         TIMESTAMPTZ,
  created_at      TIMESTAMPTZ DEFAULT NOW()
);

organizations

Corporate or hub partner entities. A user may belong to one organization.

CREATE TABLE organizations (
  id              UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  name            TEXT NOT NULL,
  slug            TEXT UNIQUE NOT NULL,              -- for dashboard URL
  contact_email   TEXT,
  country         TEXT,
  logo_url        TEXT,
  referral_code   TEXT UNIQUE NOT NULL,              -- org-level referral link
  revenue_total   NUMERIC(15,2) DEFAULT 0,           -- computed or cached
  status          TEXT DEFAULT 'active' CHECK (status IN ('active','suspended','pending')),
  approved_by     UUID REFERENCES users(id),
  approved_at     TIMESTAMPTZ,
  created_at      TIMESTAMPTZ DEFAULT NOW()
);

affiliates

Tracks affiliate link performance. Each user IS an affiliate automatically.

CREATE TABLE affiliates (
  id              UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  user_id         UUID UNIQUE NOT NULL REFERENCES users(id) ON DELETE CASCADE,
  referral_code   TEXT UNIQUE NOT NULL,              -- same as users.referral_code
  total_clicks    INTEGER DEFAULT 0,
  total_signups   INTEGER DEFAULT 0,
  total_paid      INTEGER DEFAULT 0,                 -- signups that converted to payment
  total_revenue   NUMERIC(15,2) DEFAULT 0,
  commission_rate NUMERIC(5,2) DEFAULT 10.00,       -- percentage; default 10%
  is_active       BOOLEAN DEFAULT TRUE,
  created_at      TIMESTAMPTZ DEFAULT NOW()
);

affiliate_clicks

One row per tracked click. Enables fraud detection and per-click analytics.

CREATE TABLE affiliate_clicks (
  id            UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  referral_code TEXT NOT NULL,
  ip_address    INET,
  user_agent    TEXT,
  device_hash   TEXT,                      -- hashed fingerprint for duplicate detection
  converted     BOOLEAN DEFAULT FALSE,    -- updated to TRUE when payment succeeds
  payment_id    UUID REFERENCES payments(id),
  clicked_at    TIMESTAMPTZ DEFAULT NOW()
);

achievements

Unlockable badges and milestones per user, displayed on wallet/profile.

CREATE TABLE achievements (
  id          UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  user_id     UUID NOT NULL REFERENCES users(id) ON DELETE CASCADE,
  type        TEXT NOT NULL,               -- e.g. 'first_referral', 'builder_100', '5_paid_referrals'
  label       TEXT NOT NULL,
  icon        TEXT,                        -- emoji or R2 icon URL
  unlocked_at TIMESTAMPTZ DEFAULT NOW()
);

events

Launch events. May 29 is the first. Designed for reuse for future events.

CREATE TABLE events (
  id          UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  title       TEXT NOT NULL,
  description TEXT,
  venue       TEXT NOT NULL,              -- e.g. 'Family Hall'
  starts_at   TIMESTAMPTZ NOT NULL,
  ends_at     TIMESTAMPTZ,
  is_active   BOOLEAN DEFAULT TRUE,
  created_at  TIMESTAMPTZ DEFAULT NOW()
);

event_tickets

One QR ticket per eligible user per event. Generated immediately after payment.

CREATE TABLE event_tickets (
  id              UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  event_id        UUID NOT NULL REFERENCES events(id),
  user_id         UUID NOT NULL REFERENCES users(id) ON DELETE CASCADE,
  payment_id      UUID REFERENCES payments(id),
  qr_code         TEXT NOT NULL,             -- unique token embedded in QR image
  qr_url          TEXT,                      -- R2 URL of rendered QR PNG
  checked_in      BOOLEAN DEFAULT FALSE,
  checked_in_at   TIMESTAMPTZ,

Powers the partner logo strip on the landing page.

Critical Design Decisions

  • Payment-first flow: User pays before creating an account. The email captured at checkout is the identity anchor. After payment, they are prompted to set a password or link Google.
  • Edge functions for sensitive ops: Payment webhook verification, Whop provisioning, wallet creation — all run server-side in Supabase Edge Functions, never in client code.
  • Idempotency: The webhook handler checks payments.provider_ref before processing to prevent duplicate user creation on retry.
  • Referral tracking: The affiliate referral_code is stored in a browser cookie (7-day TTL) on link click. It is read and submitted with the payment form.

Post-Payment Pipeline (shared by both providers)

This is a single atomic transaction executed inside the webhook edge function:

async function runPostPaymentPipeline(paymentData) {
  // 1. Update payments row status to 'success'
  await db.payments.update({ status: 'success', paid_at: now() });

  // 2. Create user profile (if not exists)
  const user = await db.users.upsert({ email, tier, ... });

  // 3. Generate unique referral_code (nanoid 8-char)
  const referralCode = nanoid(8).toUpperCase();
  await db.users.update({ referral_code: referralCode });

  // 4. Create wallet
  const wallet = await db.wallets.create({ user_id: user.id });

  // 5. Credit builder credits based on tier
  const credits = TIER_CREDITS[tier]; // { starter: 2000, vip: 5000, ... }
  await db.wallet_transactions.insert({ type: 'credit', amount: credits, desc: 'Welcome credits' });
  await db.wallets.update({ credit_balance: credits, lifetime_credits: credits });

  // 6. Process affiliate commission (if referred_by exists)
  if (referredBy) {
    await processAffiliateCommission(referredBy, paymentData.amount);
  }

  // 7. Provision Whop community access
  await whopAPI.createMembership({ email, tier });

  // 8. Generate event ticket QR
  await generateEventTicket(user.id, MAY_29_EVENT_ID);

  // 9. Send email confirmation
  await resend.sendWelcomeEmail(email, { user, wallet, qrUrl });

  // 10. Send WhatsApp confirmation
  await whatsapp.sendTemplate(phone, 'dot_welcome', { name, tier });

  // 11. Track PostHog event
  await posthog.capture('payment_success', { tier, amount, currency, referred_by });
}

Affiliate System

How It Works

  1. Every user automatically receives a unique referral_code on account creation.
  2. Their referral link is: https://joindot.africa/r/[referral_code]
  3. The /r/[code] Next.js route sets a cookie: dot_ref=CODE; max-age=604800 (7 days), then redirects to /join?ref=CODE.
  4. At checkout, the ref param or cookie is embedded as a hidden field in the payment form and stored in payments.affiliate_code.
  5. When payment succeeds, the webhook handler calls processAffiliateCommission().

Commission Processing

async function processAffiliateCommission(referralCode, paymentAmount) {
  const affiliate = await db.affiliates.findByCode(referralCode);
  if (!affiliate || !affiliate.is_active) return;

  const commission = paymentAmount * (affiliate.commission_rate / 100);

  // Credit reward_balance on the affiliate's wallet
  await db.wallets.increment({ reward_balance: commission });
  await db.wallet_transactions.insert({
    type: 'reward',
    amount: commission,
    description: `Referral commission from ${paymentAmount}`,
    reference: referralCode
  });

  // Update affiliate stats
  await db.affiliates.increment({
    total_paid: 1,
    total_revenue: paymentAmount
  });

  // Update the referred user's record
  await db.users.update({ referred_by: referralCode });

  // Check and grant achievements
  await checkAffiliateAchievements(affiliate.user_id);
}

  • Org referral link — joindot.africa/r/[org.referral_code] with copy button
  • Member table — name, tier, joined date (no sensitive data)

Org Referral Link

The organization has its own referral_code that credits the org account. When a user signs up via the org link, they are automatically linked to the organization (users.organization_id is set). Org revenue is computed from all member payments.

Check-in Edge Function Logic

async function handleCheckin(token, ops_user_id) {
  const ticket = await db.event_tickets.findByQR(token);

  if (!ticket) return error('INVALID_TOKEN');
  if (ticket.checked_in) return error('ALREADY_CHECKED_IN', ticket.checked_in_at);

  await db.event_tickets.update({
    checked_in: true,
    checked_in_at: now(),
    checked_in_by: ops_user_id
  });

  // Award reputation points for attending
  await db.wallets.incrementReputation(ticket.user_id, 150);
  await grantAchievement(ticket.user_id, 'launch_event_attendee');

  return success({ user: ticket.user, tier: ticket.user.tier });
}

Security & RLS Policies

Core RLS Policies

-- users: users can only read/update their own row
ALTER TABLE users ENABLE ROW LEVEL SECURITY;
CREATE POLICY "users_self_select" ON users FOR SELECT USING (auth.uid() = id);
CREATE POLICY "users_self_update" ON users FOR UPDATE USING (auth.uid() = id);
-- Admin override: service_role key bypasses RLS (used only in edge functions)

-- wallets: user can read their own wallet
ALTER TABLE wallets ENABLE ROW LEVEL SECURITY;
CREATE POLICY "wallet_self_select" ON wallets FOR SELECT USING (user_id = auth.uid());
-- NO INSERT/UPDATE/DELETE from client — wallets modified only by edge functions

-- wallet_transactions: user can read own transactions
ALTER TABLE wallet_transactions ENABLE ROW LEVEL SECURITY;
CREATE POLICY "txn_self_select" ON wallet_transactions
  FOR SELECT USING (wallet_id IN (SELECT id FROM wallets WHERE user_id = auth.uid()));

-- affiliates: user can read own stats
ALTER TABLE affiliates ENABLE ROW LEVEL SECURITY;
CREATE POLICY "aff_self_select" ON affiliates FOR SELECT USING (user_id = auth.uid());

-- organizations: org_admin can see own org
ALTER TABLE organizations ENABLE ROW LEVEL SECURITY;
CREATE POLICY "org_admin_select" ON organizations FOR SELECT
  USING (id IN (SELECT organization_id FROM users WHERE id = auth.uid()));

-- event_tickets: user can read own ticket
ALTER TABLE event_tickets ENABLE ROW LEVEL SECURITY;
CREATE POLICY "ticket_self_select" ON event_tickets FOR SELECT USING (user_id = auth.uid());

-- Public read-only tables (no auth required)
CREATE POLICY "partner_logos_public" ON partner_logos FOR SELECT USING (active = TRUE);
CREATE POLICY "faqs_public" ON faqs FOR SELECT USING (active = TRUE);
CREATE POLICY "events_public" ON events FOR SELECT USING (is_active = TRUE);

Admin Access

Admin functions use the Supabase service_role key which bypasses RLS entirely. This key is stored only in Supabase Edge Function secrets and never exposed to the browser or Next.js client.

Webhook Security

// Paystack: verify X-Paystack-Signature header
const hash = crypto.createHmac('sha512', PAYSTACK_SECRET_KEY)
  .update(JSON.stringify(body)).digest('hex');
if (hash !== req.headers['x-paystack-signature']) return 401;

// Stripe: verify Stripe-Signature header
const event = stripe.webhooks.constructEvent(
  rawBody, req.headers['stripe-signature'], STRIPE_WEBHOOK_SECRET
);

Additional Security Measures

  • All Next.js routes protected by Middleware using @supabase/ssr session check
  • HTTPS enforced on all endpoints (Vercel + Cloudflare)
  • Rate limiting on payment initiation endpoint (max 5 requests/minute per IP)
  • Input sanitization on all form fields before DB write
  • PostHog events never include PII (no email/phone in event properties)
  • R2 bucket for QR codes is public-read; URLs are non-guessable UUIDs
